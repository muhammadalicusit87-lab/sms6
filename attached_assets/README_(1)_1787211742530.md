# School Management System (SMS) — Offline Desktop App
### Built for a local private school in Pakistan

## 1. Overview

A fully **offline**, desktop-based School Management System for a single-campus private school in Pakistan. It replaces registers and Excel sheets with one local application that stores everything on the school's own computer — no internet required, no cloud dependency, no monthly subscription.

The system has exactly **two user roles**:

| Role | Who it's for | Access level |
|---|---|---|
| **Owner** | School owner / principal | Full access to everything, including financial reports, staff salaries, user management, and system settings/backup |
| **Manager** | Front-office / admin manager | Day-to-day operations: admissions, attendance, fee collection, exam entry — no access to salary data, profit/expense summaries, or system settings |

Because it's offline-first, all data lives in a local database file on the school's PC. The Owner can back up / restore this file manually (e.g., to a USB drive) — there is no server, no login over the internet, and no third-party data sharing.

## 2. Research Notes — Why These Features (Pakistan Context)

Based on how private schools in Pakistan actually operate and what commercial Pakistani school-ERP products (fee/exam/attendance-focused systems) commonly offer, the following realities shaped these requirements:

- **Fee structure is complex**: admission fee, monthly tuition, annual/security fund, exam fee, transport fee (optional), late fine, sibling discounts, scholarships, and partial/installment payments are all common.
- **Boards vary**: schools may follow the **Matric (BISE) system** or **Cambridge O/A-Level**, each with different grading scales — the system should allow a custom grading scheme per class rather than one fixed grade table.
- **Attendance and fee defaulters** are the two things owners care about most day-to-day.
- **Result cards / report cards** are usually printed physically for parents, so PDF-style printable report cards matter more than online parent portals.
- **Sibling/family linking** matters — many students share a guardian and a combined fee receipt.
- Schools regulated under provincial education authorities (e.g., PEIRA in Punjab) need to retain proper admission and academic records — the system should never allow hard-deletion of core records, only soft-delete/archive.
- **Urdu names** alongside English are common on ID cards and certificates — the system should support both.
- SMS/WhatsApp and online payment gateways (JazzCash/EasyPaisa) are common in commercial products but require internet — these are explicitly **out of scope** for this offline version and listed only under Future Enhancements.

## 3. Tech Stack

| Layer | Technology |
|---|---|
| Frontend | **TypeScript**, React (via Vite), Electron (for offline desktop packaging) |
| Backend (Phase 2) | **Node.js + TypeScript**, Express (runs locally, packaged inside/alongside the Electron app) |
| Database | **PostgreSQL** running locally on the school's PC (no internet needed — it's a local service, not a cloud DB), accessed via **Prisma ORM** (or `pg`/`node-postgres`) |
| State management | React Context / Zustand |
| Styling | Tailwind CSS |
| PDF/Reports | `pdf-lib` or `puppeteer`-based HTML-to-PDF for receipts, report cards, ID cards |
| Packaging | Electron Builder (single installable `.exe` for Windows, since most Pakistani schools use Windows PCs), bundling a local PostgreSQL installer/service (e.g. via `pg-embedded` style bundling or a bundled Windows PostgreSQL service installed on first run) |
| Backup | "Export Backup" / "Restore Backup" buttons that run `pg_dump` / `pg_restore` (or `pg_dumpall`) against the local PostgreSQL instance, saving a `.sql`/`.dump` file to a folder the Owner chooses (USB-drive friendly) |

> **Build order**: Frontend UI first (with mock/local data), then wire up the Node.js + TypeScript backend with PostgreSQL, then connect them via Electron's local IPC or a `localhost` Express API talking to `localhost:5432`.

> **Note on "offline" with PostgreSQL**: PostgreSQL still runs entirely on the same machine as a local Windows service — there is no external network call involved. The installer should set up the local Postgres service and create the database automatically so the school doesn't need to configure anything manually.

## 4. User Roles & Permissions

### Owner (full access)
- Everything the Manager can do, PLUS:
- View/edit fee structure & pricing
- View income vs. expense reports, profit summaries
- Manage staff salaries and payroll
- Create/manage the Manager's login account
- Access system settings, database backup & restore
- Delete/archive records (soft-delete only)
- Configure academic year, classes, sections, subjects, grading scheme

### Manager (operational access)
- Student admission & profile management
- Daily attendance marking (students & staff)
- Fee collection & receipt printing (cannot change fee structure)
- Exam marks entry & report card generation
- Timetable viewing/editing (if permitted by Owner)
- View basic dashboards (attendance %, fee collected today, etc.)
- **Cannot** see salary, expenses, profit, or system settings

Login is a simple local username + password (bcrypt-hashed, stored in SQLite) — no email/OTP needed since there's no internet.

## 5. Core Modules

### 5.1 Authentication
- Local login screen (Owner / Manager)
- Password change, "remember me" on trusted device
- Session auto-logout after inactivity (configurable)

### 5.2 Dashboard
- Owner dashboard: total students, today's fee collected, monthly income/expense summary, attendance % today, upcoming exams
- Manager dashboard: today's attendance status, pending admissions, fee due today

### 5.3 Student & Admission Management
- New admission form: student name (English + Urdu), father/guardian name & CNIC, DOB, gender, address, contact number, previous school, class/section applying for, photo upload
- Auto-generate unique **Admission/Registration Number**
- Sibling linking (link students under one guardian/family)
- Student profile — a 360° view: personal info, class history, fee ledger, attendance record, exam results, documents
- Promote/Demote students to next class at year-end (bulk action)
- Mark student as Left/Struck-off (soft delete, keeps historical record)

### 5.4 Class & Section Management
- Create classes (Nursery → O/A-Level or Matric) and sections (A, B, C)
- Assign class teacher
- Set subjects per class
- Set fee structure per class

### 5.5 Fee Management
- Configurable fee heads: Admission Fee, Monthly Tuition, Annual Fund, Exam Fee, Transport Fee, Miscellaneous
- Per-student adjustments: sibling discount, scholarship, custom discount (Owner-only)
- Monthly fee challan/voucher generation (single or bulk, printable)
- Fee collection screen — mark paid, partial payment, late fee/fine auto-calculation by due date
- Fee ledger per student (all dues, payments, balance)
- Defaulter list/report (unpaid fees by month/class)
- Daily/monthly fee collection report

### 5.6 Attendance
- Daily attendance marking per class/section (Present/Absent/Leave/Late)
- Staff attendance separately
- Monthly attendance register (printable, class-wise)
- Attendance % report per student (useful for exam eligibility)

### 5.7 Examination & Results
- Create exams (Monthly Test, Mid-Term, Final Term, etc.) per class
- Define subjects & max marks per exam
- Marks entry screen (per class/subject)
- Configurable grading scale per class (supports both Matric-style % grading and Cambridge-style letter grading)
- Auto-calculate total, percentage, grade, position/rank in class
- Printable report card per student (English + school letterhead)
- Class-wise result summary/toppers list

### 5.8 Staff / HR Management (Owner-only visibility for salary)
- Staff profile: name, CNIC, contact, designation, subject(s)/class assigned, joining date, salary
- Staff attendance
- Monthly salary/payroll register, salary slip printing
- Leave record

### 5.9 Timetable
- Weekly timetable builder per class/section
- Teacher-wise timetable view (avoid clashes)
- Printable class timetable

### 5.10 Reports & Analytics (mostly Owner)
- Fee collection report (daily/monthly/yearly, by class)
- Defaulter report
- Attendance summary report
- Exam result summary report
- Income vs. expense report (fees in vs. salaries/expenses out)
- Student strength report (enrollment by class over time)

### 5.11 Expense Management (Owner-only)
- Log school expenses (utilities, maintenance, supplies, salaries) by category
- Monthly expense summary, compared against fee income

### 5.12 Settings & Backup (Owner-only)
- School profile: name, logo, address, contact — used on receipts/report cards/ID cards
- Academic year setup
- Manage Manager's account (create/reset password/disable)
- **Backup Now** → exports the SQLite `.db` file with timestamp to a folder chosen by the Owner
- **Restore Backup** → replaces current data with a chosen backup file
- App version / data storage location info

### 5.13 ID Cards & Certificates (optional but recommended)
- Printable student ID card template (photo, name, class, admission #, school logo)
- Character certificate / leaving certificate/ Bonafide certificate templates

## 6. Non-Functional Requirements

- **Offline-first**: the app must be fully usable with zero internet connection at all times.
- **Single-machine local storage**: all data in one local PostgreSQL database running as a Windows service on the school's PC; no cloud sync in this version.
- **Data safety**: no hard deletes on student/fee/exam records — soft delete/archive only, to satisfy record-keeping needs.
- **Performance**: must comfortably handle a school of up to ~2,000 students without slowdown.
- **Printable output**: receipts, challans, report cards, ID cards, and registers must be print-ready (A4/thermal-receipt friendly where relevant).
- **Simple installation**: single installer, no separate database server setup required by the school.
- **Role-based UI**: Manager should never even see Owner-only screens/menu items, not just be blocked from acting on them.
- **Localization-ready**: UI should support English text with Urdu names/fields where relevant (right-to-left field support for Urdu name inputs).
- **Backup reminders**: gentle on-screen reminder if no backup has been taken in X days.

## 7. Suggested Database Schema (PostgreSQL, high level)

> Use PostgreSQL-native types where useful — `SERIAL`/`UUID` for ids, `ENUM` types for `role`, `status`, `gender`, etc., `TIMESTAMP` for dates, and `NUMERIC` for money fields (never `FLOAT` for fees/salaries).

```
users (id, username, password_hash, role[owner|manager], created_at, is_active)
students (id, admission_no, name_en, name_ur, father_name, guardian_cnic, dob, gender,
          address, contact, class_id, section_id, family_id, photo_path, status[active|left], created_at)
families (id, guardian_name, guardian_contact)
classes (id, name, order_index)
sections (id, class_id, name, class_teacher_id)
subjects (id, class_id, name)
fee_heads (id, name, default_amount)
fee_structure (id, class_id, fee_head_id, amount)
fee_transactions (id, student_id, month, fee_head_id, amount_due, amount_paid,
                   discount, fine, paid_date, status[paid|partial|unpaid], receipt_no)
attendance_students (id, student_id, date, status[present|absent|leave|late])
attendance_staff (id, staff_id, date, status)
staff (id, name, cnic, contact, designation, subject_ids, salary, joining_date, status)
salary_payments (id, staff_id, month, amount_paid, paid_date)
exams (id, name, class_id, term, date)
exam_marks (id, exam_id, student_id, subject_id, marks_obtained, max_marks)
expenses (id, category, description, amount, date)
school_settings (id, school_name, logo_path, address, contact, academic_year)
```

## 9. Development Phases

1. **Phase 1 — Frontend (this build)**: React + TypeScript UI for all modules above, using local mock/in-memory data, with Owner vs Manager views fully separated.
2. **Phase 2 — Backend**: Node.js + TypeScript + Express + PostgreSQL (via Prisma), replacing mock data with real local persistence; wire into Electron.
3. **Phase 3 — Packaging**: Electron Builder installer that also installs/configures the local PostgreSQL service, backup/restore via `pg_dump`/`pg_restore`, first-run setup wizard (create school profile + Owner account).
4. **Phase 4 (Future/Optional)**: WhatsApp/SMS parent notifications, online fee payment (JazzCash/EasyPaisa), multi-branch support, parent-facing app — all require internet and are **not** part of this offline version.

## 10. Out of Scope (for this version)

- Parent or student login portal
- SMS/WhatsApp notifications
- Online payment gateway integration
